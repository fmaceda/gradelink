# Backlog — GradeLink

## How to use this file

- `/suggest-features` adds proposals here (the Product Owner suggests; the
  user decides — nothing becomes Accepted without an explicit yes).
- `/plan-release` schedules Accepted items into a release and records the
  release in `docs/releases/`. It also adds defects from `docs/MEMORY.md` Known
  Issues here when you choose to fix them in a release.
- Never delete an entry; change its status. Rejected entries stay so the same
  idea isn't re-proposed without a reason.
- IDs are `FEAT-001`, `FEAT-002`, … in the order they were proposed.

**Statuses:** `Proposed` (awaiting decision) · `Deferred` (good, not now) ·
`Accepted` (will do, unscheduled) · `Scheduled (vX.Y.Z)` · `Released
(vX.Y.Z)` · `Rejected`.

## Entry format

### FEAT-001: {{Title}}

- **Type:** new feature | improvement | gap | defect
- **Status:** Proposed
- **Proposed on:** {{date}}
- **Why / user value:** {{problem it solves, for which user, tied to PRD
  goals or what's actually built}}
- **Requirements:**
  - {{The system shall …}}
- **Acceptance criteria:**
  - {{Given / When / Then, or checklist}}
- **Evidence:** {{docs/code this is based on}}
- **Effort (estimate):** S | M | L
- **Risks / dependencies:** {{…}}
- **Decision:** {{who decided, when, and any note}}
